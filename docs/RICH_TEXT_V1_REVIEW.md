# ZIRVƏ V1: Rich Text, Bülletenlər и Analitika

Исходная разработка и проверки ниже выполнены на `main` (`f19f3a2`) до применения миграции. Актуальный статус внедрения указан в конце отчёта.

1. **Редактор.** Общий `RichTextEditor` на TipTap 3 / ProseMirror используется для создания документов, создания и редактирования бюллетеней. Поддерживаются bold/italic/underline, H1–H3, абзацы, цитаты, вложенные списки, ссылки, клавиатурные команды и undo/redo. Toolbar переносится на узких экранах; активные состояния, доступные подписи и ошибки локализованы. Чтение использует общий `RichTextContent` с той же типографикой. Markdown-редактор удалён; Markdown остаётся только для форматирования ответов AI.

2. **Хранение и валидация.** В `documents` и `daily_briefs` добавлено обязательное `body_rich jsonb`: обычный ProseMirror JSON `{ type: "doc", content: [...] }`. Это единственное авторитетное содержимое. Разрешены только определённые узлы, marks и атрибуты; проверяется грамматика дерева. Ограничения: глубина 24, 50 000 узлов, сериализованный JSON до 4 MB; текст до 200 000 UTF-16 единиц для бюллетеня и 500 000 для документа. Пустые абзацы/форматирование и невидимый пустой текст не удовлетворяют обязательному заполнению. Управляющие символы, некорректный Unicode и небезопасные URL отклоняются. Презентационные атрибуты ссылок TipTap удаляются перед хранением.

3. **Текст для поиска и AI.** Сервер валидирует JSON, строит `body` и сохраняет оба поля одной операцией в существующей транзакции. Клиентский `body` игнорируется. `projectRichText()` обходит текстовые блоки по порядку: между заголовками/абзацами, включая пункты списков, вставляет два LF; `hardBreak` становится одним LF. Текст не обрезается и не нормализуется. SQL-функция `public.rich_text_plain()` повторяет проекцию; CHECK constraints запрещают расхождение полей даже при прямой записи в БД.

4. **Индексация и citations.** Оба индексатора используют `chunkRichDocument()`: разделы определяются узлами заголовков, границы абзацев и пунктов списков учитываются при разбиении. Каждый `chunk.text` равен `body.slice(charStart, charEnd)`; UTF-16 offsets и emoji проверены. Рендерер использует карту отдельных текстовых узлов из той же проекции и выделяет точный диапазон, включая частичные слова, marks и переносы. Никакого поиска фрагмента по совпадению строк или пересчёта смещений через Markdown нет. Переход по UUID chunk, проверки доступа, актуальности источника и сохранённых citations сохранены. Изменения структуры Rich JSON также ставят бюллетень в очередь индексации; прежняя защита от выдачи устаревшего текста сохранена.

5. **Word paste.** Clipboard HTML разбирается в изолированном DOM и заново собирается по allowlist. Сохраняются семантические заголовки, жирный/курсив/подчёркивание, ссылки, абзацы, цитаты, обычные списки и Word `MsoListParagraph` / `mso-list`, включая вложенность и начальный номер. Inline font/color/layout styles, Word metadata, скрипты, unsafe URL и внешние объекты удаляются. Plain-text paste не интерпретирует Markdown-маркеры. Образец `İnfo Büllüten 01.10.2026.docx` прочитан без изменения исходного файла: 287 абзацев, 55 элементов списков, 32 363 UTF-16 единицы в текстовой проекции. В браузер передан построенный из DOCX Word-подобный HTML; сохранение текста, числа абзацев/пунктов и повторное открытие JSON проверены. Содержимое образца хранится только в игнорируемых локальных артефактах, в tracked fixtures — синтетические тексты.

6. **Bülletenlər.** Поле ручного заголовка удалено. Сервер назначает `İnformasiya bülleteni`, игнорируя попытки клиента передать другое название. Обязательная дата остаётся отдельным полем; карточка акцентирует дату с годом, название показывается тише, excerpt строится из plain text. Detail также акцентирует дату. UUID, классификация, права редактирования и работа вложений сохранены; уникальность даты не вводится.

7. **Analitika.** Добавлен `Bülletenlərdə də axtar` / `includeBriefs`, default OFF. OFF выполняет только document branches; ON включает обе группы источников. Период и запрет будущих дат действуют на обе группы, direction/reliability — только на document-часть SQL OR. Старые history filters получают false; явное значение сохраняется и загружается. RRF, rerank, Gemini models, prompts, RESULT_LIMIT=10 и Context Expansion не изменены.

8. **Миграция и порядок запуска.** Подготовлены `0025_rich_text_documents.sql`, Drizzle snapshot и journal. Миграция создаёт функцию проекции, обязательные колонки и CHECK constraints, не содержит backfill, reset, truncate или удаления данных. Перед её применением `documents` и `daily_briefs` должны быть пустыми: это сознательная миграция без поддержки старого Markdown. Владелец отдельно сохраняет резервную копию, останавливает приём материалов/индексаторы и подготавливает пустую БД или самостоятельно очищает выбранную БД. Затем применяет миграции по порядку до 0025 и только после этого запускает обновлённое приложение и workers. Старую очередь нельзя направлять на записи без Rich JSON. Очистка, production migrations и reindex здесь не запускались. Существующие live verification scripts обновлены под `bodyRich` и новые фильтры, но не выполнялись.

9. **Проверки.** `bun --no-env-file x tsc --noEmit` — PASS. `bun --no-env-file run lint` — PASS, одно существовавшее ранее предупреждение Fast Refresh в `src/components/ui/button.tsx`. Полный безопасный suite — **554/554 теста, 70 файлов**; транспорт и сервисы под mocks, SQL-миграция проверяется встроенным PGlite только в `memory://`. Проверены SQL/JS projection parity, атомарные записи, ограничения JSON, XSS, Word/plain paste, toolbar, shortcuts, undo/redo, большие документы, chunking, точные highlights, права, history и OFF/ON branch dispatch. `bun --no-env-file run build` — PASS (Vercel production output создан локально). Сборке потребовалось разрешение чтения файловых ссылок родительского каталога для Nitro tracing. Предупреждения сборщика о `vite-tsconfig-paths` и `attachments.test.ts` существовали до задачи.

10. **Ограничения и ручное ревью.** Реальная production БД и Gemini не вызывались; применение миграции и полный сценарий с production jobs остаются за владельцем. Браузерный smoke запускает компоненты отдельно от authenticated приложения; серверные операции покрыты изолированными тестами. Проверен DOM paste с Word HTML и HTML из реального DOCX, а не нативная операция копирования из запущенного Microsoft Word. Файл не импортируется редактором напрямую. Визуально жирные заголовки без Word heading styles остаются жирными абзацами. Изображения загружаются существующим отдельным механизмом; таблицы, шрифты, цвета и точная вёрстка Word не входят в Rich schema.

Браузерная проверка без БД: `bun --no-env-file run scripts/verify-rich-editor-browser.ts`. Опционально принимает пути к HTML образца и JSON-массиву его абзацев. Скриншоты desktop/mobile находятся в `.release-backup.local/rich-editor/` и не входят в Git. Production build не публикуется автоматически.

## Применение миграции — 23 октября 2026, Asia/Baku

- С отдельного явного разрешения владельца удалены ровно 10 оставшихся документов и 81 зависимый поисковый фрагмент. Вложения отсутствовали; аккаунты и две записи истории поиска сохранены без изменений. Удаление выполнено в транзакции с проверкой количества и зависимостей.
- Настроенные application/migration connections проверены: одна Supabase БД. Миграции 0000–0024 соответствуют журналу; исторические различия hashes объясняются исключительно LF/CRLF, SQL совпадает. Записи журнала не переписывались.
- `bun --no-env-file run db:migrate` успешно применил 0025 стандартным Drizzle migrator. В журнале 26 миграций; hash и timestamp 0025 совпадают с файлом в Git.
- Проверены обе обязательные колонки `body_rich JSONB NOT NULL`, immutable/strict SQL projection function и оба validated CHECK constraints. SQL-проекция совпадает с приложением. Короткий smoke на временных копиях схемы подтвердил принятие корректного JSON и отказ при рассогласованном `body` либо NULL JSON; вся smoke-транзакция откатилась. Реальные материалы не создавались. Первая версия smoke-скрипта дважды кодировала JSON при прямом использовании postgres.js; после подключения того же Drizzle-адаптера, что в приложении, проверка прошла. Код приложения и миграция не менялись.
- Итоговые количества: documents=0, daily_briefs=0, chunks=0, analytics_queries=2. Gemini, reindex, повторный полный suite и browser E2E не запускались.
- Изменения подготовлены для одного обычного commit/push в `main`. Ручной deployment и изменения environment variables не выполнялись. После push требуется дождаться автоматического Vercel deployment нужной revision перед ручным тестированием; IDs/triggers Inngest не менялись.
