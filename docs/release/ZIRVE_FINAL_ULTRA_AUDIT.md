# ZIRVƏ V1 — финальный аудит

Дата: 22 октября 2026 года, Asia/Baku. Проверяется локальная рабочая версия на основе `main`, HEAD `2aea2805da6280ec3d76e85f0f39d2e98721e654`.

**Итог: NO-GO для безусловного production release.** Исправления интерфейса, истории и проверки доступа подготовлены и технически проверены. Однако контрольная генерация выявила существенную ошибку аналитического вывода; сравнительный запрос достиг действующего deadline. Последние точечные уточнения prompt не имеют полного повторного семантического подтверждения. Успешные unit tests и build не заменяют эту проверку.

## A. DeepSeek Audit

На старте обнаружены 12 staged файлов, без unstaged и untracked изменений. Изучены `AGENTS.md`, обе части Git diff, последние commits, документация, компоненты и серверные проверки. Опубликованная история Git не переписывалась.

Сохранены правильные решения DeepSeek: одна карточка на исходный материал, группировка по идентификатору родителя и типу, оригинальные номера фрагментов, разделение материалов и фрагментов, раскрытие исходного документа/бюллетеня. Retrieval, RRF, optional reranking, лимит результатов, chunking и embeddings не менялись.

Исправлены обнаруженные дефекты:

- История считала источники по пустому списку текущего SSE-запроса, показывая нулевые счётчики. Теперь она использует собственные авторизованные mappings.
- Неполные snapshots приводились к preview через небезопасный type cast. Теперь legacy-данные получают явную безопасную форму без выдуманного текста фрагмента.
- Повторный переход к тому же anchor не раскрывал карточку; закодированные anchors, фокус Radix и идентификаторы разных ответов создавали ошибочные переходы. Навигация теперь имеет общий scope и открывает точный фрагмент.
- Несколько номеров одного chunk создавали недоступные anchors. Все номера сохраняются, chunk учитывается один раз.
- Несколько фрагментов первоначально раскрывались сразу; карточки теперь компактны, а переход по цитате раскрывает их автоматически.
- Отсутствие одной оценки скрывало вторую. Доступные оценки сохранены независимо.
- Режим `sources` существовал на сервере, но не имел кнопки в интерфейсе. Восстановлена `Yalnız mənbələr`.
- Staged prompt-test содержал недопустимый Unicode regex и не загружался. Исправлены также ошибочные групповые фикстуры и повреждённый текст тестов; проверки смысла счётчиков, композиции и навигации сохранены и расширены.
- При отклонении повторного открытия истории предыдущий ответ оставался видимым. Теперь ответ, источники и контекст очищаются.

## B. Executive Analytics Quality

Переработан `src/server/prompts/analytics.ts`. Краткий фактический вопрос требует прямого ответа со статусом, датой и единицами. Обзор, сравнение и оценка рисков требуют содержательных связанных абзацев и синтеза доступных фактов. Нет фиксированного числа слов или обязательного набора разделов. Таблицы и заголовки используются по смыслу.

`Məhdudiyyətlər` не является стандартным завершением. Существенная неопределённость объясняется рядом с соответствующей мыслью; прямой вопрос об ограничениях допускает полный отдельный анализ. Оценки A–F/1–6 остаются метаданными и используются в тексте по смысловой необходимости, особенно при вопросе о достоверности. Предупреждения о действительно слабых источниках сохранены.

Добавлены инструкции по естественному официально-деловому азербайджанскому, согласованию и терминологии, корректуре, статусам бюджетных/производственных показателей, причинным связям и условным сценариям. Отсутствие опубликованных показателей ограничивает оценку, а само по себе не доказывает слабость объекта. Внутренние M-обозначения групп не должны попадать в ответ. Несколько chunks одного материала не считаются независимым подтверждением.

Смысловые фрагменты ответа не удаляются regex. Серверная валидация цитат, существующая нормализация их формата, token ceilings 4096/6144, модели, fallback и квоты сохранены. Валидация подтверждает допустимость номеров и техническое завершение, но не логическую истинность каждого вывода.

## C. Sources, Citations и Security

Материалы группируются по `documentId` или `briefId` с отдельным пространством типов; заголовок не является идентификатором. Счётчики различают процитированные и найденные материалы/фрагменты, исключают недоступные источники и повторные chunks. Непроцитированные фрагменты не входят в cited count. При отсутствии цитат в ответе retrieved count не выдаётся за cited count.

Popover сохраняет название, дату, раздел и excerpt. `Mənbə kartı`, `Fraqmentə bax` и ссылки на номера раскрывают точный chunk, прокручивают и переводят фокус. Проверены повторный hash, Escape/Tab/Enter, disclosure с клавиатуры, touch, длинные metadata и отсутствие горизонтального переполнения. Markdown не исполняет HTML/scripts/images и не принимает модельный URL как источник перехода; Copy сохраняет исходный полный Markdown ответа. Regenerate сохраняет исходный вопрос/фильтры и блокирует повторный запуск.

История повторно проверяет активность аккаунта, роль, clearance, доступность parent и точного текущего chunk. Недоступные данные не восстанавливаются из сохранённых caption/answer. Legacy snapshots без точного chunk сохраняют только текущие разрешённые метаданные родителя и переход; ответ подавляется. Неизвестные, повторяющиеся или неоднозначные citation mappings отклоняются. Ошибка SSE и оборванный stream очищают previews/частичный ответ. Поздний результат отменённого provider не запускает новый generation retry.

Сравнение sources при публикации проверяет точное соответствие номера, chunk, типа и parent. Уменьшение clearance отзывает также возможность публикации ответа на вопрос, введённый на более высоком уровне, даже если найденные материалы открыты. Проверка live аккаунта выполняется и при пустом retrieval.

Новые права, обходы авторизации, изменения схемы БД/формата history, моделей, квот, secrets и production environment не вводились. Существующий внешний processing boundary не расширялся. Проверочные записи БД/S3 принадлежат только текущим синтетическим запускам; основной корпус не очищался и не переиндексировался.

## F. Final Verdict

**NO-GO для безусловного production release.** Технические исправления готовы к review. Ключевой остающийся риск — содержательная ошибка C, которую обычная citation-membership validation закономерно не обнаруживает; D не дал готового ответа в действующем бюджете. Состояние не объявляется production-ready по успешному build.

Условия повторного решения о выпуске:

1. Проверить финальный prompt реальными ответами, особенно C/D/E: отсутствие показателей ограничивает оценку, а не сам объект; сравнение завершается в принятом бюджете; внутренние коды и неподтверждённый статус не попадают в текст. Сопоставить все ключевые выводы с материалами и принять качество азербайджанского.
2. Подтвердить фактическую production revision/runtime, smoke history/revocation и доставку/восстановление cloud indexing по [release runbook](RELEASE_RUNBOOK.md). Локальное исполнение worker не доказывает облачную доставку.
3. Принять полный согласованный diff. Push в connected branch и deployment требуют отдельного разрешения владельца; published history не переписывать.
